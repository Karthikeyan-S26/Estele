SECTION 4: PRODUCTION ROUTING DIAGNOSIS (CORRECTED ROOT CAUSE)
===================================================================
Root Cause of 404:
- Production returns Laravel's router 404 "The route api/home could not be
  found." (String originates in
  backend/vendor/laravel/framework/src/Illuminate/Routing/AbstractRouteCollection.php:44)
  -> Laravel IS running; the /api routes are simply NOT in the route table.
- Evidence that production Laravel is alive and serving:
  * GET /  -> 200 full storefront (web routes registered & working)
  * GET /up -> 200 "Application up / HTTP request received /
               Response rendered in 54ms." (health route registered)
- Evidence that the /api group is missing on production:
  * GET /api/health, /api/home, /api/categories, /api/collections,
    /api/search  -> all 404 "The route api/* could not be found."
- Framework analysis (ApplicationBuilder.php:196-265): web, api and health
  routes are all registered inside ONE routing closure. A compiled route
  cache containing /up MUST therefore also contain /api/*. The observed
  mix (web+health OK, api 404) is therefore IMPOSSIBLE with the current
  bootstrap/app.php - PROVING the production server is not running this code.
- Conclusion: the Hostinger production backend is running an OLD Laravel
  (stock bootstrap/app.php skeleton: web + commands + health, NO api:
  entry). The mobile API backend (bootstrap/app.php with api: registration,
  routes/api.php, Api controllers) exists only in git branches and was
  NEVER deployed to production.
- APP_URL is NOT a cause. It was ruled out definitively.

LOCAL PROOF THAT THE REPO CODE IS CORRECT (run today):
- php artisan serve on port 8021:
  * GET /api/health -> 200 {"status":"ok","service":"estele-api","time":"..."}
  * GET /api/home    -> 200 JSON, 111,418 bytes
- php artisan about -> Laravel 13.21.1, Routes NOT cached
